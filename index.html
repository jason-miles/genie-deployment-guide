Genie deployment guide: from proof of concept to enterprise rollout

Eight steps for taking a Genie Agent from a working demo to a governed, monitored service. Each step gives the action, the gate to pass, and the failure modes seen in practice.

00

Choose your path

Genie is a family of three experiences on one governed data foundation. Pick the one that matches the job before planning a rollout. This guide follows the Genie Agent lifecycle; Genie One is the way business users reach Agents, and Genie Code is a separate developer track.

0.5 Deployment controls

  • Unity Catalog is the security boundary. An Agent defines the experience; grants, row filters and column masks define what a user can query.
  • One domain per Agent. Narrow Agents answer more accurately than broad ones. Split when scope grows.
  • An owner for every Agent. Agents without an owner lose accuracy as terms and data change.
  • A benchmark gate before production. See Step 04.
  • Channels after quality. Add Teams, Slack or custom apps only once the Agent is production-quality.

01

Discover & scope

Rank candidate topics, name two stakeholders, and write down the questions before any configuration starts. Most stalled rollouts trace back to scope, not technology.

Last verified: 17 Oct 2026 against Databricks documentation. Durations and targets in this step are field-recommended starting points, not published limits.

1.1 What makes a good first topic

  • The data is already registered in Unity Catalog. Delta tables are best but not required. Unregistered data delays the start.
  • A small number of well-documented tables. Start with one to five and prove that related questions are answered correctly before expanding. An Agent accepts up to 50 tables, views or metric views, but accuracy falls as scope grows.
  • Primary and foreign keys are defined and columns have descriptions.
  • The audience is mostly business users. Technical users benefit, but the productivity gain shows most with less technical users.
  • There is a backlog of dashboard and analysis requests for the topic, a large pool of potential users, and the most-used dashboards map to the dataset.
Poor first topicsMetrics where a wrong answer carries severe risk, such as figures in a board report, belong in a reviewed dashboard or a certified query. Open-ended questions that ask for an explanation instead of a data lookup (“why are sales down”) need a different design; test them against the Agent before promising them.

1.2 Rank the candidates

List several topics and rank them. The first topic suggested is rarely the one most likely to succeed. Score each from 1 to 3 and start with the highest total.

CriterionQuestion to ask3 points when
Data readinessIs the data in Unity Catalog and documented?Registered, curated, columns described
Business valueIs there a backlog of requests for this topic?A long backlog and a named decision it speeds up
AudienceHow many business users would ask questions?Dozens or more, across more than one team
StakeholdersAre a business and a technical stakeholder committed?Both named, with time set aside
Error toleranceWhat happens if an answer is wrong?Answers support exploration, not sign-off

1.3 Name two stakeholders

StakeholderRole
Business stakeholderRepresents the end users, preferably someone who is not technical. Defines the questions, the business value and the vocabulary, and promotes the Agent to the user group.
Technical stakeholderOwns the Agent: sets it up, configures it, monitors it, and judges whether the SQL is correct. Typically a BI developer, data analyst or data modeller.

Having both protects the Agent. If one person leaves, the other keeps it alive. Without a business stakeholder, the technical owner tends to chase perfect accuracy while the business users wait.

1.5 Check the data model against the questions

Review the technical stakeholder’s data model before building. Look for a few tables joined by defined primary and foreign keys, ideally a star schema with one fact table at one grain. Avoid duplicate or near-identical column names, mixed currencies, categorical columns with hundreds of distinct values used in filters, and calculations done on the fly. Put calculations in derived columns or views. Run the following to see how much documentation exists:

-- Table-level descriptions for the candidate schema
SELECT table_name, comment
FROM {{cat:main}}.information_schema.tables
WHERE table_schema = '{{sch:sales}}';

-- Columns that still have no description
SELECT table_name, column_name
FROM {{cat:main}}.information_schema.columns
WHERE table_schema = '{{sch:sales}}' AND (comment IS NULL OR comment = '');

02

Data & governance

Make the data trustworthy and the access model explicit before the Agent exists. Genie turns a question into SQL from table and column metadata, so poor metadata produces poor SQL.

Last verified: 17 Oct 2026 against Databricks documentation. Items marked field guidance were not found in public documentation; confirm them with the account team.

2.1 Use curated tables

LayerUse for an Agent?Why
Raw / BronzeAvoidQuality problems, cryptic column names and incomplete records make answers unreliable.
Cleaned / SilverUseValidated, standardised, consistent types.
Aggregated / GoldPreferClearer business logic and pre-calculated metrics.

2.2 Prepare each table in Unity Catalog

Must have

Should have: primary and foreign keys, and governance tags for PII and sensitivity. Good to have: OPTIMIZE unless predictive optimisation is on, and a documented freshness cadence.

COMMENT ON TABLE {{cat:main}}.{{sch:sales}}.{{tbl:orders}}
  IS 'One row per customer order. Refreshed daily.';

ALTER TABLE {{cat:main}}.{{sch:sales}}.{{tbl:orders}}
  ALTER COLUMN order_total COMMENT 'Order value in USD including tax';

-- Keys are informational in Unity Catalog; they tell Genie how tables join
ALTER TABLE {{cat:main}}.{{sch:sales}}.{{tbl:orders}} ALTER COLUMN order_id SET NOT NULL;
ALTER TABLE {{cat:main}}.{{sch:sales}}.{{tbl:orders}} ADD CONSTRAINT orders_pk PRIMARY KEY (order_id);

Put metadata on table and column descriptions first. Only the relevant subset is sent with each prompt, which leaves more context for the question. Avoid repeating column semantics in general instructions.

2.3 Metric Views and the Ontology

A Metric View defines a KPI once in Unity Catalog and applies it wherever the view is queried, so Genie uses the approved definition instead of rebuilding the formula. Prefer Metric Views over Agent-level SQL expressions when a KPI is shared across Agents. An Agent accepts up to 50 tables, views or metric views; start with five or fewer, and use Metric Views or views to pre-join detail instead of adding tables. Genie Ontology adds a semantic layer of business terms, metrics and relationships, governed through metric views, Pages and Domains. It is described in a Databricks blog post and marked Public Preview in the Genie Code documentation, so treat its behaviour as subject to change.

2.6 Grant access with Unity Catalog

GRANT USE CATALOG ON CATALOG {{cat:main}} TO `{{grp:analysts}}`;
GRANT USE SCHEMA ON SCHEMA {{cat:main}}.{{sch:sales}} TO `{{grp:analysts}}`;
GRANT SELECT ON TABLE {{cat:main}}.{{sch:sales}}.{{tbl:orders}} TO `{{grp:analysts}}`;

Row filters and column masks defined in Unity Catalog apply to Genie answers based on the querying user.

CREATE FUNCTION {{cat:main}}.{{sch:sales}}.region_filter(region STRING)
  RETURN is_account_group_member('global_sales') OR region = 'EMEA';
ALTER TABLE {{cat:main}}.{{sch:sales}}.{{tbl:orders}}
  SET ROW FILTER {{cat:main}}.{{sch:sales}}.region_filter ON (region);

CREATE FUNCTION {{cat:main}}.{{sch:sales}}.mask_email(email STRING)
  RETURN CASE WHEN is_account_group_member('pii_readers') THEN email ELSE '***' END;
ALTER TABLE {{cat:main}}.{{sch:sales}}.customers
  ALTER COLUMN email SET MASK {{cat:main}}.{{sch:sales}}.mask_email;
Hiding is not access controlHiding a column in the Knowledge Store changes what Genie considers. It does not stop a user who has SELECT from querying the column elsewhere. Use grants, filters and masks.

03

Build the Agent

An Agent can be created in minutes and is only worth trusting after curation. Build a thin version first, then add structure in layers, using the most structural layer that can express each rule.

Last verified: 17 Oct 2026 against Databricks documentation. The ten-day plan is a field-recommended playbook, not a fixed schedule; a build typically takes one to four weeks from zero.

3.1 The curation hierarchy

Work down this list. Reserve text for behaviour that nothing above it can express. The documentation puts SQL expressions first among Agent-level options, example SQL second and text instructions last.

  1. Unity Catalog metadata. Accurate table and column descriptions, keys and tags. The same work helps every other consumer of the catalog.
  2. Metric Views. Live in Unity Catalog, not in the Agent. They give a deterministic KPI definition that applies wherever the view is referenced.
  3. SQL expressions. Named measures, filters and dimensions in the Agent, reused instead of reinvented per question.
  4. Parameterised example SQL. Verified queries mapped to common question patterns; when a question matches, Genie can use the query directly.
  5. Text instructions. Terminology, formatting and clarification behaviour. They iterate quickly but are open to interpretation.

Each Agent has a limit of 100 instructions, where every example SQL query, every SQL function and the whole general-instructions block counts as one.

3.2 What the Knowledge Store holds

Table and column descriptions, synonyms, join relationships, SQL expressions, prompt matching settings and column values. Everything in it is scoped to the Agent and does not change Unity Catalog. Turn on entity matching for categorical columns (regions, statuses, product names) so a prompt that says “Florida” resolves to a stored value of “FL”, and enable format assistance on important columns so Genie sees representative values. Define join relationships so joins are consistent, or pre-join frequently joined tables into views.

3.3 Sample questions

Configure 6 to 10 sample questions per Agent. Write literal questions with the real metrics and entities the Agent owns, not templated placeholders, and mirror the patterns your trusted assets cover:

  • What was revenue for Q1 2026?
  • Who are the top 10 customers by bookings this year?
  • How does gross margin compare across regions?

3.4 Example configuration

-- SQL expression (measure): net revenue
SUM(order_total) - SUM(returns_total)

-- Parameterised example SQL, with the phrasing it answers in a comment
-- "What was revenue for EMEA in Q1?"  "Show Q1 EMEA sales"
SELECT SUM(order_total) AS revenue
FROM {{cat:main}}.{{sch:sales}}.{{tbl:orders}}
WHERE region = :region AND order_quarter = :quarter;

3.6 Troubleshooting

SymptomFix
Misunderstands jargonPrecise column descriptions and Agent-scoped synonyms; example SQL that shows the interpretation; short text for critical terms
Uses the wrong tablesRemove extra tables; pre-join into governed views or metric views; say in table descriptions which table is authoritative
Uses the wrong columnsHide internal columns; clearer names and descriptions; entity matching on representative columns
Filters on values that do not existSample values for key dimensions; define canonical filters as SQL expressions
Joins incorrectlyMove joins upstream into views with explicit keys; document joins in the Knowledge Store and example SQL where keys cannot be set

High-stakes answersFor financial reporting, compliance or safety questions, encode the logic as SQL expressions and trusted assets (parameterised queries or SQL functions) instead of free-form generation, and keep a gold-question benchmark suite that validates every change.
04

Benchmark & validate

A production Agent is one that has measured accuracy. Benchmark first, let technical users live with the Agent, then bring in business power users.

Last verified: 17 Oct 2026 against Databricks documentation. Durations and the accuracy target are field guidance and are not published limits.

4.1 Build the benchmark suite

A benchmark is a question paired with the SQL that answers it correctly. Cover the 15 to 20 questions users are most likely to ask, with two to four phrasings each: roughly 30 to 80 benchmarks. An Agent supports up to 500. Use the auto-suggested benchmarks to seed the set. Cover these categories:

  • Simple aggregations: “What is total revenue?”
  • Time-based queries: “How did sales compare month over month?”
  • Filtered queries: “Show me only enterprise customers.”
  • Multi-table joins: “Which products did our top customers buy?”
  • Top-N rankings: “Who are our top 10 accounts by revenue?”
  • Complex business logic: “What is our customer churn rate?”

Benchmarks run as independent conversations without threaded context. In chat mode a result counts as good when the SQL matches exactly or the result set matches, allowing for different sorting and rounding to the same four significant digits.

4.2 Run and read results

Run the suite after every significant change to instructions or data, and track the score over time. The benchmark evaluation commands are in Beta and may change.

# Start a benchmark run, then read it back (Beta commands)
databricks genie genie-create-eval-run {{spc:01ef0000000000000000000000000000}} --profile <profile>
databricks genie genie-get-eval-run {{spc:01ef0000000000000000000000000000}} <eval-run-id> --profile <profile>
databricks genie genie-list-eval-results {{spc:01ef0000000000000000000000000000}} <eval-run-id> --profile <profile>
The 80% gateField guidance is to hold an Agent at about 80% benchmark accuracy before promoting it. This number is not in the public documentation, so treat it as a starting point and set the threshold per use case. Below the gate, an Agent is not ready regardless of how it feels in a demo.

Onboard about five business power users, preferably those who defined the scope. Temporary workspace access with SQL entitlements and permission to run the Agent is enough; the full access setup comes in Step 05. Run this for 1 to 2 weeks (field-recommended). Major changes restart the timer.

05

Access & consumption

Provision the users, then choose how they reach the Agent. This step can run in parallel with business validation in Step 04.

Last verified: 17 Oct 2026 against Databricks documentation. Setup durations are field-recommended. Items marked field guidance were not found in public documentation; confirm them with the account team.

5.1 Choose the consumption channel

Start with the Genie Agent UI and the dashboard companion to validate. Add Genie One for the broad business rollout once the Agent is production-quality. Add other channels for specific needs, because each one adds scope your team maintains. Adding a channel to a marginal Agent only spreads the wrong answers wider.

5.2 Provision users

First, make users account-level identities. Users must exist in the Databricks account before a workspace can include them. There are no seat-based licences, and data stays secured by Unity Catalog, so provision as many intended users as you can.

  • Automatic Identity Management (AIM) for Microsoft Entra ID syncs users, groups and service principals without enterprise application setup, supports nested groups, and respects group membership changes. It is GA and, per field guidance, on by default for accounts created after 1 Aug 2025; older accounts enable it under Account console, Security, User provisioning.
  • Account-level SCIM for other identity providers such as Okta. Enable user provisioning in the account console, copy the SCIM token and URL into the identity provider’s connector, and assign users and groups there.

Second, add them to a workspace with Consumer access. Consumer access is the least-privileged entitlement that is enough for Genie One chat. Add the account group, not individuals, and grant only Consumer access so business users do not receive authoring entitlements. Pick the workspace by topology:

  • One workspace: add them there.
  • Dev, staging, prod in one region: use the production workspace, so users consume production content.
  • Several workspaces or regions: either add users to each workspace that holds content they need, or create a dedicated consumer workspace and publish the Agents and dashboards to it with bundles or the Agents API.

Business users need SELECT on the Unity Catalog objects the Agents use, granted through groups. Share each Agent with the group at CAN RUN. Sharing options include workspace folder inheritance, specific users or groups, all account users, a link for privileged users, and individual conversations. A custom account URL, where available, lets users sign in once and move across workspaces; this is field guidance.

# Smoke-test an Agent from the CLI as the signed-in user
databricks genie start-conversation {{spc:01ef0000000000000000000000000000}} "What was revenue last quarter?" --profile <profile>

# Ask a data question without targeting one Agent
databricks genie ask "What tables exist?" --profile <profile>

5.3 Build on the Conversation API

  • Authenticate with OAuth: service principal OAuth (M2M) for unattended workloads, user OAuth (U2M) where a browser flow exists. A user token keeps per-user Unity Catalog privileges.
  • Poll message status every 1 to 5 seconds until it is COMPLETED, FAILED or CANCELLED, back off exponentially up to one minute, and stop after about 10 minutes.
  • Start a new conversation for each user session, so earlier context does not leak into the next.
  • Add request queuing, retry logic and logging in the calling application.
  • The API returns tables and SQL, not rendered charts. Render visuals in your own UI.
  • Every Genie query still runs on the attached warehouse. Plan warehouse capacity separately from API rate limits.
  • Field guidance on limits: 20 questions per minute per workspace in the UI and 5 per minute on the API free tier, across all Agents, with only POST requests counted. These figures are not in the public documentation; confirm them and ask about higher capacity.
06

Monitor & operate

An Agent without an owner and a review cadence loses accuracy within weeks. Set up monitoring, alerts and a feedback loop before the first wave.

Last verified: 17 Oct 2026 against Databricks documentation. Cadences are field-recommended starting points. Items marked field guidance were not found in public documentation.

6.1 The Monitor tab

Agent owners see every question and answer, with filters for time, rating, user and status, plus a weekly digest of message volume, active users and feedback. Users answer “Is this correct?” with Yes, Fix it or Request review, and anyone with CAN MANAGE reads the feedback and review requests. Ratings do not change the Agent on their own; the owner decides what to act on.

6.2 Audit logs and system tables

Genie events land in system.access.audit with service_name = 'aibiGenie'. 

-- Daily Genie message volume and distinct users, last 30 days
SELECT event_date,
       COUNT(*) AS messages,
       COUNT(DISTINCT user_identity.email) AS users
FROM system.access.audit
WHERE service_name = 'aibiGenie'
  AND action_name = 'createConversationMessage'
  AND event_date >= current_date() - INTERVAL 30 DAYS
GROUP BY event_date
ORDER BY event_date;

The SQL that Genie generated is in system.query.history. Filtering on query_source.genie_space_id is field guidance; confirm the column on your workspace. 

SELECT executed_by, start_time, total_duration_ms, execution_status, statement_text
FROM system.query.history
WHERE query_source.genie_space_id = '{{spc:01ef0000000000000000000000000000}}'
ORDER BY start_time DESC
LIMIT 100;

Cost and capacity appear in system.billing.usage (warehouse consumption) and system.compute.warehouse_events (scaling triggered by Genie load).

6.3 Alerts

There is no Genie-native alert. Configure Databricks SQL Alerts on queries over the audit and warehouse tables for: spikes in conversations or users, spikes in negative feedback, rising error rates, usage approaching the rate limits, and the SQL warehouse breaking its SLA.

6.5 The feedback-to-curation loop

  1. Capture thumbs, review requests and repeated unanswered questions from the Monitor tab.
  2. Triage one-off issues apart from repeatable gaps; prioritise questions tied to important workflows.
  3. Curate instructions, trusted assets and entity matching, using the most structural layer (Step 03).
  4. Validate by re-running the relevant benchmarks and checking that nothing else regressed.
  5. Record and observe. Log the change in a curation log and watch the same question patterns.

07

Staged rollout & promotion

Grow from a pilot to the full audience in waves, and promote the tested configuration between environments instead of rebuilding it by hand.

Last verified: 17 Oct 2026 against Databricks documentation. Wave sizes and timings are field-recommended. The migration sequence follows a published bundle-based pattern; commands are untested here until marked.

7.1 Roll out in waves

Work backwards from the end state: the number of users, and the peak of concurrent questions in the busiest hour. Advance a wave only when the Agent has not changed, or leave a couple of days after any change.

WaveAudienceWhenHold until
110 usersWeek 0Stability confirmed, feedback triaged
250 usersAbout 2 to 3 weeks laterDepartment-scale usage monitored, instructions iterated
3200 usersAbout 3 to 5 weeks after wave 1Warehouse and review capacity confirmed
4+Enterprise-wideWeek 6 onwardIncrease exponentially after the first stages

In the first weeks, the admin team and the onboarded users should work closely to resolve what the earlier steps did not anticipate. Around 500 concurrent users, or sustained high API volume, validate routing, warehouse sizing, queuing and latency early.

7.2 Go/no-go before each wave

CheckGo when
Benchmark accuracyAt or above the agreed target on the latest run
WarehouseWithin SLA at the current peak, with headroom for the next wave
Rate limitsNo alert for approaching the question-per-minute limits

When close to a limit: increase warehouse size or autoscaling; staff the review queue; and, for API throughput, ask the account team about higher capacity options.

7.3 Roll back

  • Pause onboarding of the next group.
  • If a configuration change caused the regression, redeploy the previous exported configuration from Git (7.4).
  • If access is the problem, remove the latest wave group’s CAN RUN on the Agent. Unity Catalog grants stay untouched.
  • Tell users what changed and when to retry.

7.4 Promote between environments

Keep separate catalogs for dev, staging and production data, and re-run benchmarks before every promotion. The Agent configuration travels as a serialized export:

# Export the source Agent, including its serialized configuration
databricks genie get-space {{spc:01ef0000000000000000000000000000}} --include-serialized-space -o json --profile <dev-profile> > genie_spaces/sales_analytics.json

Edit the file for the target (catalog and schema names, and a warehouse that exists in the target workspace), commit it to Git as the audit record, then deploy. Declarative Automation Bundles manage Agents natively through the genie_spaces resource, which needs the direct deployment engine and CLI 1.3.0 or later. 

bundle:
  name: genie-agents
  engine: direct

resources:
  genie_spaces:
    sales_analytics:
      title: Sales analytics
      warehouse_id: {{wh:abcdef1234567890}}
      parent_path: /Workspace/Shared/genie

      permissions:
        - group_name: {{grp:analysts}}

targets:
  prod:
    workspace:
      host: https://<prod-workspace>.cloud.databricks.com
databricks bundle validate -t prod --profile <prod-profile>
databricks bundle deploy -t prod --profile <prod-profile>

Run the export and the deployment as service principals with the least access needed: CAN EDIT on the source Agent, and on the target CAN USE on the warehouse and CAN MANAGE on the parent folder. Without bundles, databricks genie create-space and update-space take the same serialized payload.

Top five ways rollouts stall

  1. Cross-domain Agents. One Agent for everything is less accurate than three focused ones.
  2. Skipping benchmarks. Without a suite, accuracy is invisible and degradation is undetectable.
  3. Treating Genie as a feature, not a product. No owner, backlog or cadence means decay.
  4. Confusing the UI with the security boundary. Hiding a column in the Knowledge Store is not access control.
  5. Scaling channels too early. Teams or Slack on a marginal Agent amplify the wrong answers.

Recommended first wave

Choose one representative, low-risk domain with a business and a technical stakeholder who have time set aside, five or fewer curated tables in Unity Catalog, an audience of about ten users, and no answer that carries severe risk if wrong. Use it to prove the whole path once: the metadata standard, the benchmark gate, the credential pattern, the access provisioning, the monitoring queries and the promotion from development to production. Then repeat for the next domain with the same checklist, and share patterns across Agent authors.

Developer track: Genie Code

Genie Code is the AI coding and data assistant for developers. It is not part of the Agent rollout gates and does not count toward the progress meter. Use this track to enable it safely and to speed up Agent authoring.

Show the Genie Code track

Last verified: 17 Oct 2026 against Databricks documentation.

What it does

Genie Code works as an autonomous agent by default and also offers a chat interface. It runs in notebooks, the SQL editor, the Lakeflow Pipelines Editor, AI/BI dashboards and MLflow, and has a full-page experience; a CLI also exists. Domain agents cover data science, data engineering, document processing, dashboards and MLflow. Databricks recommends reviewing any generated code before running it.

Enable it

  • Turn on partner-powered AI features at both account and workspace level. Without them Genie Code stays available but uses a Databricks-hosted model without its agentic capabilities.
  • Confirm the region supports it; Genie Code is a designated service that uses Geos for data residency. See the Databricks designated services page.
  • Account administrators manage budgets and cost controls.

Governance

Genie Code is governed by the user’s Unity Catalog permissions, so it can only reach data and perform operations the user is allowed to. It sends the prompt and relevant context to the model: table and column names, descriptions, the code in use, data samples and cell outputs, all within those permissions. Review this against your Tier 2 and Tier 3 compliance items in Step 02 before enabling it for regulated data.

Guide it with instructions and skills

  • Personal instructions live in .assistant_instructions.md in the user’s folder. Workspace-wide instructions live in .assistant_workspace_instructions.md, are set by workspace administrators and take precedence. Each file is limited to 20,000 characters, and AGENTS.md and CLAUDE.md files are picked up automatically.
  • Skills are folders with a SKILL.md file (name and description frontmatter) in Workspace/.assistant/skills/ or the user’s .assistant/skills/. Genie Code loads them when relevant or when mentioned with @. 
# Genie Agent authoring conventions
- Write table and column comments in plain business language, one sentence each.
- Name the grain of every fact table in its comment.
- Never use SELECT * in example SQL; list the columns.
- Use three-level names: {{cat:main}}.{{sch:sales}}.table.

Use it to build Agents

Suggested uses, each reviewed by the Agent owner as any other change:

  • Draft table and column descriptions, then check them against the business glossary (Step 02).
  • Draft metric view definitions and SQL expressions for the core KPIs (Step 03).
  • Write candidate benchmark SQL for the Step 01 questions, then verify each against a trusted report (Step 04).
  • Generate the audit and monitoring queries in Step 06 for your workspace.
